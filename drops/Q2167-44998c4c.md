# Palomar §2.2 semantic wording review

Audited against the current public repository head `f76e9e7a528c1abfd6ca095cff48d7ab34b3c1d2` (`Correct the public trace definition comment`), specifically the public definitions in `Challenge.lean` / `PalomarQseriesPrimeCoefficients/Public.lean` and the corresponding notation in `paper/paper3.tex`.

## Bottom line

The proposed documentation cleanup is mathematically sound. I see **no substantive overclaim** in the proposed meanings. Two items should be sharpened for Palomar §2.2 precision:

1. `DCoeff`: “in translated natural coordinates” is correct but slightly underspecified; spell out the translation `k = -(i+1)`, `r = -(j+1)` if you want the docstring to be fully self-contained.
2. `iotaCert`: do not leave the scope as merely “at admissible primes.” State the exact conditions under which the magnitude interpretation applies: `x` has norm `-p`, `p` is prime with `p % 10 = 1`, and the `SectorCert` is obtained from a `GeometricSectorCert x`. This matters because bare `SectorCert` is intentionally unconstrained and `lambdaOf` is totalized.

Everything else in the proposed list is semantically accurate as stated. I would also make one optional hardening to the already-existing `sameIdeal` docstring, discussed below, because that definition occurs directly in a selected theorem type.

## Item-by-item review

### 1. `ACoeff`

Proposed:

> “The A-cone contribution to `B_N`, including the outer minus sign.”

**PASS.**

The Lean definition is

```lean
def ACoeff (N : Nat) : Int :=
  ((Finset.range (N + 1) ×ˢ Finset.range (2 * N + 2)).filter
    (fun p => E (↑p.1) (↑p.2) = ↑N)).sum
    (fun p => -negOnePowInt (↑p.2))
```

so `ACoeff` already contains the manuscript's outer minus sign. The manuscript defines

```text
B_N = (D-cone sum) - (A-cone sum).
```

This wording is substantially better than the current “Positive-cone coefficient,” which hides the sign convention.

Recommended exact docstring:

```lean
/-- The A-cone contribution to the manuscript coefficient `B_N`, including
its outer minus sign. -/
```

### 2. `DCoeff`

Proposed:

> “The D-cone contribution to `B_N` in translated natural coordinates.”

**PASS, but slightly underspecified.**

The definition uses natural indices `p.1,p.2` and substitutes

```text
k = -(p.1 + 1),   r = -(p.2 + 1),
```

which is exactly the bijection from `Nat × Nat` to the manuscript D-cone `k<0, r<0`. Its summand has no extra outer minus sign, again matching the paper.

For maximal §2.2 self-containment, I recommend:

```lean
/-- The D-cone contribution to the manuscript coefficient `B_N`, after
writing `k = -(i+1)` and `r = -(j+1)` with natural coordinates `i,j`. -/
```

The shorter proposed wording is not false; this is a clarity improvement, not a mathematical correction.

### 3. `BCoeff`

Proposed:

> “The manuscript coefficient `B_N`: D-cone sum minus A-cone sum.”

**PASS.**

Although the Lean body is

```lean
def BCoeff (N : Nat) : Int := DCoeff N + ACoeff N
```

that is exactly D minus A because `ACoeff` already includes the minus sign. The proposed docstring correctly describes the mathematical object rather than mechanically paraphrasing the Lean `+`.

Recommended exact docstring:

```lean
/-- The manuscript coefficient `B_N`: the D-cone sum minus the A-cone sum. -/
```

### 4. `discreteLog`

Proposed requirement: disclose that zero is totalized to `0`.

**PASS, and this disclosure is important.**

The actual definition is

```lean
def discreteLog (x : ZMod 2 × ZMod 2) : ZMod 3 :=
  if x = (1, 0) then 0
  else if x = (1, 1) then 1
  else if x = (0, 1) then 2
  else 0
```

Since `ZMod 2 × ZMod 2` has exactly four elements, the final branch is precisely `(0,0)`. Thus the function agrees with the intended `F_4^×` discrete logarithm on the three nonzero residues and is artificially totalized at zero.

I recommend making both facts explicit:

```lean
/-- The discrete-log label on the three nonzero mod-two residues, with the
zero residue `(0,0)` totalized to `0`. -/
```

This avoids implying that the zero residue has an actual multiplicative discrete logarithm.

### 5. `SectorCert`

Proposed:

> it is only an indexed `ZMod 3` label and does not certify a geometric lift.

**PASS, and this is the right correction.**

The structure is literally

```lean
structure SectorCert (x : PhiInt) where
  δ : ZMod 3
```

There is no proposition tying `δ` to `x`, no lift, and no normalization proof. The dependence on `x` is only in the type index. By contrast, `GeometricSectorCert x` carries an integer lift plus a proof of `SameWindowSign` after normalization.

Recommended exact docstring:

```lean
/-- A `ZMod 3` label indexed by `x`. This record carries no geometric lift or
normalization proof; those are supplied only by `GeometricSectorCert`. -/
```

This is preferable to saying “the residue label induced by an integral sector lift,” which is not true for an arbitrary inhabitant of `SectorCert x`.

### 6. `lambdaOf`

Proposed requirement: disclose totalization.

**PASS.**

The definition is exactly

```lean
def lambdaOf (x : PhiInt) : ZMod 3 := discreteLog (toF4 x)
```

so it inherits the zero-residue totalization. A precise docstring is:

```lean
/-- The mod-two discrete-log residue label `discreteLog (toF4 x)`, totalized
to `0` when `toF4 x = (0,0)`. -/
```

That is more accurate than the current wording, which sounds as though a genuine multiplicative logarithm exists for every `x`.

### 7. `iotaCert`

Proposed:

> state only the formal difference and scope the magnitude interpretation to geometric certificates at admissible primes.

**Conceptually PASS, but tighten the scope.**

The raw definition is unconditional:

```lean
def iotaCert (x : PhiInt) (c : SectorCert x) : ZMod 3 :=
  c.δ - lambdaOf x
```

For arbitrary `c : SectorCert x`, `c.δ` is unconstrained; for even `x`, `lambdaOf x` may be the artificial totalized value. Therefore the docstring should not say that a bare `iotaCert` “governs prime magnitude.”

The public magnitude theorem applies when:

```text
Nat.Prime p
p % 10 = 1
PhiInt.norm x = -(p : Int)
c : GeometricSectorCert x
```

and the theorem uses

```text
iotaCert x c.toSectorCert.
```

So I recommend this exact wording:

```lean
/-- The formal difference `c.δ - lambdaOf x` in `ZMod 3`. Its coefficient-
magnitude interpretation is used only when `c` comes from a
`GeometricSectorCert x` for an element `x` of norm `-p`, with `p` prime and
`p % 10 = 1`. -/
```

I prefer “element `x` of norm `-p`” over “generator” here, because the public theorem type itself contains no principal-ideal object; this avoids reintroducing the ideal-theory ambiguity that the repository has carefully removed elsewhere.

Merely saying “at admissible primes” is not wrong, but is less precise than §2.2 invites because it leaves unstated that an arbitrary `SectorCert` does not receive the magnitude interpretation.

### 8. `windowComp`

Proposed:

> “The second integral fundamental-window coordinate `b-3a`.”

**PASS.**

The definition is

```lean
def windowComp (x : PhiInt) : Int := x.b - 3 * x.a
```

and the manuscript/Lean normalization uses the pair

```text
Tr(x) = 2a+b,
windowComp(x) = b-3a
```

as the two integral fundamental-window coordinates. Unlike the old “cleared-denominator form” wording, the proposed sentence states exactly what the quantity is without suggesting an unspecified denominator-clearing map.

Recommended exact docstring:

```lean
/-- The second integral fundamental-window coordinate `b - 3a`. -/
```

### 9. `PhiInt.eps`

Proposed:

> “fundamental totally positive unit `1+phi=phi^2` of norm one.”

**PASS.**

The Lean value is

```lean
def eps : PhiInt := ⟨1, 1⟩
```

which is `1+phi = phi^2`. Its norm is

```text
1^2 + 1*1 - 1^2 = 1,
```

and both real embeddings of `phi^2` are positive. The manuscript explicitly uses `eps = phi^2` as the fundamental totally positive unit and identifies the norm-one units as `±eps^m`.

Recommended exact docstring:

```lean
/-- The fundamental totally positive unit `1 + phi = phi^2`, of norm one. -/
```

No overclaim here.

### 10. `BCoeff_not_multiplicative_witness` theorem comment

Proposed: explain

```text
a(M) = B_((M-1)/10)
```

and the witness

```text
a(341) != a(11) a(31).
```

**PASS, and this is materially clearer than calling `BCoeff` itself a multiplicative arithmetic function.**

The manuscript defines, for `M ≡ 1 (mod 10)`,

```text
a(M) := B_{(M-1)/10}
```

and proves

```text
a(11)=1,
a(31)=-2,
a(341)=3,
```

hence `a(341) != a(11)a(31)`. The selected Lean theorem is the equivalent index-level statement

```lean
BCoeff 34 ≠ BCoeff 1 * BCoeff 3.
```

Recommended exact docstring:

```lean
/-- Under the manuscript reindexing `a(M) = BCoeff ((M - 1) / 10)` for
`M ≡ 1 (mod 10)`, this is the explicit witness
`a(341) ≠ a(11) * a(31)`. -/
```

This avoids the mild ambiguity in “the coefficient sequence is not multiplicative,” since multiplicativity is naturally a statement about the reindexed arithmetic function `a`, not about the raw `N ↦ BCoeff N` indexing.

## One additional optional §2.2 hardening: `sameIdeal`

This was not in the proposed list, but it occurs directly in the third Comparator theorem type, so I would consider strengthening its docstring while doing the documentation pass.

Current definition:

```lean
def sameIdeal (x y : PhiInt) : Prop :=
  ∃ (m : Int) (negative : Bool),
    y = match negative with
      | false => epsZPowMul m x
      | true => -(epsZPowMul m x)
```

Current docstring:

```lean
/-- Association by a signed norm-one unit. -/
```

That is not mathematically false, and the README / `formalization.yaml` already explicitly say that this local name is not a formal principal-ideal predicate. Still, because the identifier `sameIdeal` itself is easy to read as equality of principal ideals, the Challenge would be even more audit-proof with:

```lean
/-- The explicit signed fundamental-unit orbit relation
`y = ± eps^m x`. Despite the local name, this definition is not a
principal-ideal equality predicate. -/
```

I regard this as **optional hardening**, not a remaining mathematical defect, because the existing docstring says “association by a signed norm-one unit” and the repository's narrative already disclaims the broader ideal-theory interpretation.
